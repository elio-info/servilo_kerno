Below is a complete example of how to perform a MongoDB query (using Mongoose) that matches documents based on conditions on objects inside an array. The example is built with NestJS and follows a typical API structure (controller, service, module, schema).

## Scenario

We have a collection of `orders`. Each order document contains an array `items` where each item is an object with `name`, `price`, and `quantity`. We want to find all orders that have at least one item matching multiple criteria, e.g.:
- item name is "Laptop"
- item price is greater than 1000

This requires a query that inspects the array and applies conditions on the sub‑documents.

## 1. Define the Mongoose Schema

Create the schema using `@nestjs/mongoose` decorators.

```typescript
// order.schema.ts
import { Prop, Schema, SchemaFactory } from '@nestjs/mongoose';
import { Document } from 'mongoose';

export type OrderDocument = Order & Document;

@Schema()
export class OrderItem {
  @Prop({ required: true })
  name: string;

  @Prop({ required: true })
  price: number;

  @Prop({ required: true })
  quantity: number;
}

@Schema()
export class Order {
  @Prop({ required: true })
  orderNumber: string;

  @Prop({ type: [OrderItem], default: [] })
  items: OrderItem[];
}

export const OrderSchema = SchemaFactory.createForClass(Order);
```

## 2. Create the Module

Register the schema with Mongoose in the module.

```typescript
// orders.module.ts
import { Module } from '@nestjs/common';
import { MongooseModule } from '@nestjs/mongoose';
import { Order, OrderSchema } from './order.schema';
import { OrdersService } from './orders.service';
import { OrdersController } from './orders.controller';

@Module({
  imports: [
    MongooseModule.forFeature([{ name: Order.name, schema: OrderSchema }]),
  ],
  controllers: [OrdersController],
  providers: [OrdersService],
})
export class OrdersModule {}
```

## 3. Write the Service with the Query

In the service, we use `$elemMatch` to specify multiple conditions on the same array element. If you need to combine different criteria across the array, you can adjust the filter accordingly.

```typescript
// orders.service.ts
import { Injectable } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { Order, OrderDocument } from './order.schema';

@Injectable()
export class OrdersService {
  constructor(
    @InjectModel(Order.name) private orderModel: Model<OrderDocument>,
  ) {}

  /**
   * Find orders that contain at least one item matching the given criteria.
   * @param itemName - item name to match
   * @param minPrice - minimum price for the item
   */
  async findOrdersByItemCriteria(itemName: string, minPrice: number): Promise<Order[]> {
    // Use $elemMatch to apply multiple conditions on the same array element
    const filter = {
      items: {
        $elemMatch: {
          name: itemName,
          price: { $gt: minPrice },
        },
      },
    };

    return this.orderModel.find(filter).exec();
  }
}
```

**Explanation**  
- `$elemMatch` ensures that at least one element in the `items` array satisfies **both** conditions (`name === itemName` and `price > minPrice`).  
- If you need to match elements across the array with different conditions (e.g., an item with name "Laptop" *and* another item with quantity > 5), you would use multiple `$elemMatch` clauses or the `$and` operator. For that more complex case, see the **Advanced Note** below.

## 4. Build the Controller

Create a REST endpoint that accepts query parameters and calls the service method.

```typescript
// orders.controller.ts
import { Controller, Get, Query } from '@nestjs/common';
import { OrdersService } from './orders.service';
import { Order } from './order.schema';

@Controller('orders')
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Get('search')
  async searchOrders(
    @Query('itemName') itemName: string,
    @Query('minPrice') minPrice: string,
  ): Promise<Order[]> {
    // Convert minPrice to number (or use ValidationPipe in a real app)
    const price = parseFloat(minPrice);
    return this.ordersService.findOrdersByItemCriteria(itemName, price);
  }
}
```

## 5. Full API Sequence Example

1. **Request**  
   `GET /orders/search?itemName=Laptop&minPrice=1000`

2. **Mongoose Query**  
   The generated MongoDB query (simplified) would be:
   ```javascript
   db.orders.find({
     items: {
       $elemMatch: {
         name: "Laptop",
         price: { $gt: 1000 }
       }
     }
   })
   ```

3. **Response**  
   Returns an array of order documents that contain at least one item named "Laptop" with price > 1000.

## Advanced: Matching Multiple Criteria Across Different Array Elements

If you need to find orders where **different** items satisfy different conditions (e.g., an item named "Laptop" and another item with quantity > 5), you can combine `$elemMatch` with `$and`:

```typescript
const filter = {
  $and: [
    { items: { $elemMatch: { name: 'Laptop' } } },
    { items: { $elemMatch: { quantity: { $gt: 5 } } } },
  ],
};
```

This returns orders that contain at least one "Laptop" item **and** at least one item with quantity greater than 5 (they may be the same item or different items).

## Summary

- Use `$elemMatch` inside the array field to apply multiple conditions to the same array element.
- For cross‑element conditions, use `$and` with separate `$elemMatch` clauses.
- The same pattern works in any NestJS service using `@nestjs/mongoose`.

This example provides a complete, runnable API sequence that you can adapt to your own data models and criteria.

  Below is an extended example that retrieves **count**, **sum**, and **average** for orders matching the same criteria. The aggregation pipeline is used to compute these metrics efficiently. The example assumes you want the total value of each order (sum of `price * quantity` over all its items) and then the overall count, sum, and average of those order totals.

## 1. Service Method Using Aggregation

We'll add a method in `OrdersService` that returns the statistics.

```typescript
// orders.service.ts
import { Injectable } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { Order, OrderDocument } from './order.schema';

@Injectable()
export class OrdersService {
  constructor(
    @InjectModel(Order.name) private orderModel: Model<OrderDocument>,
  ) {}

  /**
   * Find orders matching the item criteria and return:
   * - count of orders
   * - sum of total order values
   * - average order value
   */
  async getOrderStatsByItemCriteria(itemName: string, minPrice: number): Promise<{
    count: number;
    totalSum: number;
    average: number;
  }> {
    const pipeline = [
      // Stage 1: Match orders that contain at least one item satisfying the criteria
      {
        $match: {
          items: {
            $elemMatch: {
              name: itemName,
              price: { $gt: minPrice },
            },
          },
        },
      },
      // Stage 2: Compute total value for each order
      {
        $addFields: {
          orderTotal: {
            $sum: {
              $map: {
                input: '$items',
                as: 'item',
                in: { $multiply: ['$$item.price', '$$item.quantity'] },
              },
            },
          },
        },
      },
      // Stage 3: Group to get statistics
      {
        $group: {
          _id: null,
          count: { $sum: 1 },
          totalSum: { $sum: '$orderTotal' },
          average: { $avg: '$orderTotal' },
        },
      },
    ];

    const result = await this.orderModel.aggregate(pipeline).exec();
    // If no orders match, result will be an empty array
    if (result.length === 0) {
      return { count: 0, totalSum: 0, average: 0 };
    }
    const { count, totalSum, average } = result[0];
    return { count, totalSum, average };
  }
}
```

**Explanation**  
- `$match` uses `$elemMatch` to keep only orders with an item matching `name` and `price > minPrice`.  
- `$addFields` creates a new field `orderTotal` by iterating over the `items` array with `$map`. For each item, it multiplies `price` by `quantity` and then `$sum`s the resulting array.  
- `$group` with `_id: null` aggregates all documents into one. It calculates `count` (number of orders), `totalSum` (sum of `orderTotal`), and `average` (average of `orderTotal`).  
- If no orders match, the pipeline returns an empty array; we handle that by returning zeros.

## 2. Controller Endpoint

Add a new endpoint that returns the statistics.

```typescript
// orders.controller.ts
import { Controller, Get, Query } from '@nestjs/common';
import { OrdersService } from './orders.service';

@Controller('orders')
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Get('search')
  async searchOrders(
    @Query('itemName') itemName: string,
    @Query('minPrice') minPrice: string,
  ) {
    const price = parseFloat(minPrice);
    return this.ordersService.findOrdersByItemCriteria(itemName, price);
  }

  @Get('stats')
  async getOrderStats(
    @Query('itemName') itemName: string,
    @Query('minPrice') minPrice: string,
  ) {
    const price = parseFloat(minPrice);
    return this.ordersService.getOrderStatsByItemCriteria(itemName, price);
  }
}
```

## 3. Full API Sequence Example

- **Request**  
  `GET /orders/stats?itemName=Laptop&minPrice=1000`

- **Aggregation Pipeline (simplified)**  
  ```javascript
  db.orders.aggregate([
    { $match: { items: { $elemMatch: { name: "Laptop", price: { $gt: 1000 } } } } },
    { $addFields: { orderTotal: { $sum: { $map: { input: "$items", as: "item", in: { $multiply: ["$$item.price", "$$item.quantity"] } } } } } },
    { $group: { _id: null, count: { $sum: 1 }, totalSum: { $sum: "$orderTotal" }, average: { $avg: "$orderTotal" } } }
  ])
  ```

- **Response**  
  ```json
  {
    "count": 5,
    "totalSum": 12500.75,
    "average": 2500.15
  }
  ```

## Alternative: Aggregating Over Matching Items Only

If you want the statistics based **only** on the items that match the criteria (e.g., sum of prices of matching items, average quantity of matching items), you would unwind the array, filter the items, and then group. Here's a quick example for that scenario:

```typescript
const pipeline = [
  { $unwind: '$items' },
  { $match: { 'items.name': itemName, 'items.price': { $gt: minPrice } } },
  {
    $group: {
      _id: null,
      count: { $sum: 1 },                // number of matching items
      totalPrice: { $sum: '$items.price' },
      avgQuantity: { $avg: '$items.quantity' },
    },
  },
];
```

Choose the approach that fits your business need.

## Summary

- Use aggregation pipelines in Mongoose to compute statistics across filtered documents.  
- The pipeline can be extended with multiple stages to reshape data and calculate aggregates.  
- Handle the empty result case gracefully.  

This example gives you a complete, runnable NestJS service for obtaining count, sum, and average based on array‑element criteria.

Below is an extended example that adds date range filtering to the previous statistics query. The same aggregation pipeline now includes a condition on the order date, allowing you to retrieve count, sum, and average for orders that:

- contain at least one item matching the given criteria (name, min price), **and**
- have an order date falling within a specified range.

## 1. Schema with Date Field

Add an `orderDate` field to the `Order` schema.

```typescript
// order.schema.ts
import { Prop, Schema, SchemaFactory } from '@nestjs/mongoose';
import { Document } from 'mongoose';

export type OrderDocument = Order & Document;

@Schema()
export class OrderItem {
  @Prop({ required: true })
  name: string;

  @Prop({ required: true })
  price: number;

  @Prop({ required: true })
  quantity: number;
}

@Schema()
export class Order {
  @Prop({ required: true })
  orderNumber: string;

  @Prop({ required: true, type: Date })
  orderDate: Date;                      // <-- new date field

  @Prop({ type: [OrderItem], default: [] })
  items: OrderItem[];
}

export const OrderSchema = SchemaFactory.createForClass(Order);
```

## 2. Service Method with Date Range

In the service, we accept optional start and end dates. If both are provided, we add a date range condition. The aggregation pipeline is updated accordingly.

```typescript
// orders.service.ts
import { Injectable } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { Order, OrderDocument } from './order.schema';

@Injectable()
export class OrdersService {
  constructor(
    @InjectModel(Order.name) private orderModel: Model<OrderDocument>,
  ) {}

  /**
   * Get statistics for orders that:
   * - contain at least one item with given name and price > minPrice
   * - have orderDate between startDate and endDate (if both provided)
   */
  async getOrderStatsByItemCriteria(
    itemName: string,
    minPrice: number,
    startDate?: Date,
    endDate?: Date,
  ): Promise<{
    count: number;
    totalSum: number;
    average: number;
  }> {
    // Build the $match stage step by step
    const matchConditions: any = {
      items: {
        $elemMatch: {
          name: itemName,
          price: { $gt: minPrice },
        },
      },
    };

    // Add date range if both start and end are provided
    if (startDate && endDate) {
      matchConditions.orderDate = {
        $gte: startDate,
        $lte: endDate,
      };
    } else if (startDate) {
      // only start date: from that date onward
      matchConditions.orderDate = { $gte: startDate };
    } else if (endDate) {
      // only end date: up to that date
      matchConditions.orderDate = { $lte: endDate };
    }

    const pipeline = [
      // Stage 1: Match orders based on item criteria and date range
      { $match: matchConditions },

      // Stage 2: Compute total value for each order
      {
        $addFields: {
          orderTotal: {
            $sum: {
              $map: {
                input: '$items',
                as: 'item',
                in: { $multiply: ['$$item.price', '$$item.quantity'] },
              },
            },
          },
        },
      },

      // Stage 3: Group to get statistics
      {
        $group: {
          _id: null,
          count: { $sum: 1 },
          totalSum: { $sum: '$orderTotal' },
          average: { $avg: '$orderTotal' },
        },
      },
    ];

    const result = await this.orderModel.aggregate(pipeline).exec();
    if (result.length === 0) {
      return { count: 0, totalSum: 0, average: 0 };
    }
    const { count, totalSum, average } = result[0];
    return { count, totalSum, average };
  }
}
```

**Key Points**  
- The `$match` stage now includes an `orderDate` condition when date parameters are provided.  
- You can pass `startDate` and/or `endDate` as JavaScript `Date` objects.  
- The pipeline remains efficient because all filtering happens in the first stage.

## 3. Controller with Date Query Parameters

Add the date parameters to the controller endpoint. They are expected as ISO strings (e.g., `2026-01-01`) and converted to `Date` objects.

```typescript
// orders.controller.ts
import { Controller, Get, Query } from '@nestjs/common';
import { OrdersService } from './orders.service';

@Controller('orders')
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Get('stats')
  async getOrderStats(
    @Query('itemName') itemName: string,
    @Query('minPrice') minPrice: string,
    @Query('startDate') startDate?: string,   // ISO date string
    @Query('endDate') endDate?: string,
  ) {
    const price = parseFloat(minPrice);
    const start = startDate ? new Date(startDate) : undefined;
    const end = endDate ? new Date(endDate) : undefined;
    return this.ordersService.getOrderStatsByItemCriteria(
      itemName,
      price,
      start,
      end,
    );
  }
}
```

## 4. Full API Sequence Example

- **Request**  
  `GET /orders/stats?itemName=Laptop&minPrice=1000&startDate=2026-01-01&endDate=2026-03-31`

- **Aggregation Pipeline (simplified)**  
  ```javascript
  db.orders.aggregate([
    {
      $match: {
        items: { $elemMatch: { name: "Laptop", price: { $gt: 1000 } } },
        orderDate: { $gte: ISODate("2026-01-01"), $lte: ISODate("2026-03-31") }
      }
    },
    { $addFields: { orderTotal: { $sum: { $map: { input: "$items", as: "item", in: { $multiply: ["$$item.price", "$$item.quantity"] } } } } } },
    { $group: { _id: null, count: { $sum: 1 }, totalSum: { $sum: "$orderTotal" }, average: { $avg: "$orderTotal" } } }
  ])
  ```

- **Response**  
  ```json
  {
    "count": 3,
    "totalSum": 8700.50,
    "average": 2900.17
  }
  ```

## Handling Edge Cases

- If `startDate` is provided without `endDate`, the query matches orders from that date onward.  
- If `endDate` is provided without `startDate`, it matches orders up to that date.  
- If neither date is given, no date filtering is applied.  

You can easily adjust the logic to require both dates or to treat missing dates differently.

## Summary

- The same aggregation pipeline can be extended to filter by a date range by adding conditions to the `$match` stage.  
- Use JavaScript `Date` objects when constructing queries to ensure proper MongoDB ISODate conversion.  
- The controller accepts ISO date strings and converts them.  

This gives you a complete, flexible NestJS API endpoint to retrieve order statistics based on item criteria and a date range.

Below is the final extended solution that adds **partial matching on the item name** (case‑insensitive) to the previous statistics query with date range filtering. Now you can retrieve count, sum, and average for orders that:

- contain at least one item whose name contains the given substring (case‑insensitive),
- have a price greater than a specified minimum,
- and have an order date within an optional range.

## 1. Schema (unchanged)

The `Order` schema includes `orderDate` and an array of `items`.

```typescript
// order.schema.ts
import { Prop, Schema, SchemaFactory } from '@nestjs/mongoose';

@Schema()

  @Prop({ required: true })
  name: string;

  @Prop({ required: true })
  price: number;

  @Prop({ required: true })
  quantity: number;
}

@Schema()
export class Order {
  @Prop({ required: true })
  orderNumber: string;

  @Prop({ required: true, type: Date })
  orderDate: Date;

  @Prop({ type: [OrderItem], default: [] })
  items: OrderItem[];
}
```

## 2. Service with Partial Name Matching and Date Range

In the service, we build the `$match` stage dynamically. For the item name, we use a case‑insensitive regular expression. A helper function escapes any regex‑special characters in the user input.

```typescript
// orders.service.ts
import { Injectable } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { Order, OrderDocument } from './order.schema';

@Injectable()
export class OrdersService {
  constructor(
    @InjectModel(Order.name) private orderModel: Model<OrderDocument>,
  ) {}

  // Escape special characters for regex
  private escapeRegex(text: string): string {
    return text.replace(/[-[\]{}()*+?.,\\^$|#\s]/g, '\\$&');
  }

  /**
   * Get statistics for orders that:
   * - contain at least one item whose name contains the given substring (case‑insensitive)
   * - with price > minPrice
   * - and orderDate between startDate and endDate (if provided)
   */
  async getOrderStatsByItemCriteria(
    itemName: string,
    minPrice: number,
    startDate?: Date,
    endDate?: Date,
  ): Promise<{
    count: number;
    totalSum: number;
    average: number;
  }> {
    // Build the $match stage conditions
    const matchConditions: any = {
      items: {
        $elemMatch: {
          name: { $regex: this.escapeRegex(itemName), $options: 'i' }, // partial, case‑insensitive
          price: { $gt: minPrice },
        },
      },
    };

    // Add date range if provided
    if (startDate && endDate) {
      matchConditions.orderDate = { $gte: startDate, $lte: endDate };
    } else if (startDate) {
      matchConditions.orderDate = { $gte: startDate };
    } else if (endDate) {
      matchConditions.orderDate = { $lte: endDate };
    }

    const pipeline = [
      { $match: matchConditions },
      {
        $addFields: {
          orderTotal: {
            $sum: {
              $map: {
                input: '$items',
                as: 'item',
                in: { $multiply: ['$$item.price', '$$item.quantity'] },
              },
            },
          },
        },
      },
      {
        $group: {
          _id: null,
          count: { $sum: 1 },
          totalSum: { $sum: '$orderTotal' },
          average: { $avg: '$orderTotal' },
        },
      },
    ];

    const result = await this.orderModel.aggregate(pipeline).exec();
    if (result.length === 0) {
      return { count: 0, totalSum: 0, average: 0 };
    }
    const { count, totalSum, average } = result[0];
    return { count, totalSum, average };
  }
}
```

**What changed for partial name matching?**  
- Inside `$elemMatch`, the `name` field now uses `{ $regex: escapedInput, $options: 'i' }`.  
- This matches any item whose name contains the substring `itemName` (case‑insensitive).  
- The `escapeRegex` method ensures that characters like `.`, `*`, `+` in the search term are treated as literals, not regex operators.

## Performance Consideration

Using a regular expression with a leading wildcard (as in `$regex: "lapt"`) **cannot use an index** on the `items.name` field efficiently. If your collection is large and you need high performance, consider:

- Using a **text index** and `$text` search (which supports word stems but not arbitrary substrings).
- Storing a lower‑case version of the name and using a `$regex` with the `^` anchor if you only need prefix matching.
- If substring search is a hard requirement, you might explore Elasticsearch or MongoDB Atlas Search.

For moderate‑sized collections, the regex approach is acceptable and very flexible.

## Summary

- **Partial name matching** is achieved with a case‑insensitive `$regex` inside `$elemMatch`.  
- The input is escaped to avoid regex injection or unintended patterns.  
- The date range filtering remains optional and works seamlessly with the new name condition.  
- The aggregation pipeline computes order totals and then aggregates to return count, sum, and average.

This completes the full feature set: matching array objects by multiple criteria (partial name, minimum price) and a date range, then returning summary statistics.

We need to adapt the previous example to a schema where an `Order` has **two separate arrays** of items: `itemsA` and `itemsB`, each containing sub‑documents of type `OrderItem`.  
The goal is to:

1. **Match** orders based on criteria applied to either array (or both).
2. **Compute per‑order statistics** for each array separately (count, total price, average price) as well as overall combined statistics for the order.
3. **Aggregate overall** statistics across all matching orders.

Below is a complete explanation and code using NestJS + Mongoose.

---

## 1. Updated Schemas

## 2. Service with Aggregation

We want to filter orders that contain **at least one item** in `itemsA` **or** `itemsB` that matches the criteria (e.g., name = "Laptop", price > 1000).  
Then compute statistics per array and overall.

### Aggregation pipeline strategy

- **`$match`** – filter orders using `$or` with two `$elemMatch` conditions (one for each array).
- **`$addFields`** – create a combined array `allItems` by concatenating `itemsA` and `itemsB` (useful for overall stats).
- **`$project`** – keep original arrays and the combined array.
- **`$unwind`** – unwind `itemsA`, `itemsB`, and `allItems` separately? That would multiply documents. Instead, we can use **`$facet`** inside the group stage to compute stats for each array separately without cross‑unwinding.

A cleaner approach:  
1. Use `$facet` at the end to produce two parallel aggregations: one for per‑order stats, one for overall stats.  
2. For per‑order stats, we need to compute for each order:
   - `itemsACount`, `itemsATotalPrice`, `itemsAAvgPrice`
   - `itemsBCount`, `itemsBTotalPrice`, `itemsBAvgPrice`
   - `totalItemsCount`, `totalPrice`, `overallAvgPrice`

We can do this by **unwinding each array separately** and then grouping by order, using conditional sums.

But to avoid complexity, we can use **`$project` with `$size`, `$reduce`, `$avg`** to compute stats without unwinding (available in MongoDB 3.4+). This is more efficient.

Here's a pipeline that uses `$reduce` to compute totals:

```typescript
// orders.service.ts
import { Injectable } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { Order, OrderDocument } from './order.schema';

@Injectable()
export class OrdersService {
  constructor(
    @InjectModel(Order.name) private orderModel: Model<OrderDocument>,
  ) {}

  async getOrderStatistics(itemName: string, minPrice: number) {
    const pipeline = [
      // 1. Filter orders that have at least one matching item in itemsA OR itemsB
      {
        $match: {
          $or: [
            { itemsA: { $elemMatch: { name: itemName, price: { $gt: minPrice } } } },
            { itemsB: { $elemMatch: { name: itemName, price: { $gt: minPrice } } } },
          ],
        },
      },
      // 2. Compute per‑order statistics using $addFields and $reduce
      {
        $addFields: {
          // Statistics for itemsA
          itemsACount: { $size: '$itemsA' },
          itemsATotalPrice: {
            $reduce: {
              input: '$itemsA',
              initialValue: 0,
              in: { $add: ['$$value', { $multiply: ['$$this.price', '$$this.quantity'] }] },
            },
          },
          itemsAAvgPrice: {
            $cond: [
              { $eq: ['$itemsACount', 0] },
              null,
              { $divide: ['$itemsATotalPrice', '$itemsACount'] },
            ],
          },
          // Statistics for itemsB
          itemsBCount: { $size: '$itemsB' },
          itemsBTotalPrice: {
            $reduce: {
              input: '$itemsB',
              initialValue: 0,
              in: { $add: ['$$value', { $multiply: ['$$this.price', '$$this.quantity'] }] },
            },
          },
          itemsBAvgPrice: {
            $cond: [
              { $eq: ['$itemsBCount', 0] },
              null,
              { $divide: ['$itemsBTotalPrice', '$itemsBCount'] },
            ],
          },
          // Combined stats (all items)
          totalItemsCount: { $add: ['$itemsACount', '$itemsBCount'] },
          totalPrice: { $add: ['$itemsATotalPrice', '$itemsBTotalPrice'] },
          overallAvgPrice: {
            $cond: [
              { $eq: ['$totalItemsCount', 0] },
              null,
              { $divide: ['$totalPrice', '$totalItemsCount'] },
            ],
          },
        },
      },
      // 3. Use $facet to separate per‑order results from overall totals
      {
        $facet: {
          perOrder: [
            {
              $project: {
                orderNumber: 1,
                itemsA: { count: '$itemsACount', totalPrice: '$itemsATotalPrice', avgPrice: '$itemsAAvgPrice' },
                itemsB: { count: '$itemsBCount', totalPrice: '$itemsBTotalPrice', avgPrice: '$itemsBAvgPrice' },
                total: { count: '$totalItemsCount', totalPrice: '$totalPrice', avgPrice: '$overallAvgPrice' },
              },
            },
          ],
          overall: [
            {
              $group: {
                _id: null,
                totalOrders: { $sum: 1 },
                totalItemsA: { $sum: '$itemsACount' },
                totalItemsB: { $sum: '$itemsBCount' },
                totalPriceA: { $sum: '$itemsATotalPrice' },
                totalPriceB: { $sum: '$itemsBTotalPrice' },
                totalCombinedPrice: { $sum: '$totalPrice' },
                // Average price across all items (overall)
                avgPriceOverall: { $avg: '$overallAvgPrice' },
              },
            },
            {
              $project: {
                _id: 0,
                totalOrders: 1,
                totalItemsA: 1,
                totalItemsB: 1,
                totalPriceA: 1,
                totalPriceB: 1,
                totalCombinedPrice: 1,
                avgPriceOverall: 1,
              },
            },
          ],
        },
      },
    ];

    const result = await this.orderModel.aggregate(pipeline).exec();
    return result[0]; // { perOrder: [...], overall: [...] }
  }
}
```

**Key points:**

- **`$match` with `$or`** – we check both arrays independently.
- **`$addFields`** – we compute counts and totals using `$size` and `$reduce`.  
  - `$reduce` iterates over each array, accumulating `price * quantity`.
  - For averages, we guard against division by zero with `$cond`.
- **`$facet`** – splits the output into:
  - `perOrder`: each order’s stats (array‑specific and combined).
  - `overall`: global sums across all matched orders.

## 5. Explanation of Key Aggregation Operators

- **`$or` with `$elemMatch`** – matches orders where **either** array contains at least one item satisfying the conditions.
- **`$size`** – returns the number of elements in an array.
- **`$reduce`** – iterates over the array, applying an expression to accumulate a result. Here we multiply `price * quantity` and add to the accumulator.
- **`$cond`** – conditional operator used to avoid division by zero when calculating average.
- **`$facet`** – allows multiple aggregations within the same pipeline, producing separate result sets.

---

## 6. Performance Considerations

- **`$reduce`** performs the calculation on the server without unwinding the arrays, which is more efficient than `$unwind` when you only need aggregates per array.
- If the arrays are very large, consider indexing on the fields used in `$elemMatch` to speed up the initial filter.

This approach gives you complete flexibility: you can modify the criteria in the `$match` stage, add additional filters, or compute different metrics by adjusting the `$addFields` expressions.
